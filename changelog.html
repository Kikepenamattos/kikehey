📋 Protocolo de Push y Actualización de Changelog

▶

Documentación completa del proceso que se ejecuta cada vez que se solicita hacer push al repositorio y actualizar el changelog. Este protocolo garantiza que cada commit genere una card única con toda su información.

1
Commit de Cambios
Se realiza un commit de los archivos modificados con un mensaje descriptivo que explica los cambios realizados.
git add [archivos]
git commit -m "Mensaje descriptivo del commit"
2
Ejecución del Hook post-commit
Automáticamente se ejecuta el hook .git/hooks/post-commit que captura la información del commit recién creado.
Información capturada:
• Hash completo del commit
• Autor (nombre)
• Email del autor
• Fecha y hora del commit
• Mensaje del commit
3
Actualización de git_history.txt
El hook agrega una nueva línea al archivo git_history.txt con el formato: hash|author|email|date|message
Formato:
3168b1be66503216339d71d5b6e6292ec3217bf3|Ubits|ubits@macbookpro.lan|2025-12-02 15:08:34 -0500|Update: Actualizar changelog con últimos cambios
4
Actualización Completa del Changelog (OBLIGATORIO)
⚠️ IMPORTANTE: Siempre ejecutar ./update-changelog-complete.sh antes de hacer push. Este script asegura que git_history.txt esté sincronizado con todos los commits del repositorio antes de actualizar changelog.html.
./update-changelog-complete.sh
Proceso automático:
1. Sincroniza git_history.txt: Obtiene todos los commits del repositorio (remoto o local) y los agrega a git_history.txt si faltan
2. Actualiza changelog.html: Ejecuta update-changelog-html.js que lee git_history.txt y actualiza el array realCommits
3. Verifica cambios: Muestra qué archivos fueron modificados

Este paso es CRÍTICO para evitar que las cards no se actualicen.
5
Push al Repositorio
Opción A: Usar git-push-with-changelog.sh (automático) o Opción B: Push manual seguido de update-changelog-complete.sh.
Opción A (Recomendado):
./git-push-with-changelog.sh
• Hace push de los commits
• Sincroniza commits remotos con git_history.txt
• Actualiza datos embebidos automáticamente
• Hace commit y push de los archivos actualizados

Opción B (Manual):
git push
./update-changelog-complete.sh (EJECUTAR DESPUÉS)
git add git_history.txt changelog.html
git commit -m "Update: Changelog actualizado"
git push
6
Carga del Changelog
Cuando se abre changelog.html, la función loadChangelog() intenta cargar los commits desde GitHub o usa los datos embebidos como fallback.
Orden de carga:
1. Intenta cargar desde GitHub (git_history.txt)
2. Si falla, intenta cargar localmente
3. Si falla, usa datos embebidos (realCommits)
7
Parsing de Commits
La función parseGitHistory() convierte cada línea del historial en un objeto commit con toda su información estructurada.
Estructura del objeto commit:
• hash: Hash corto (7 caracteres)
• fullHash: Hash completo
• author: Nombre del autor
• email: Email del autor
• date: Fecha y hora del commit
• message: Mensaje del commit
8
Prevención de Errores y Solución de Problemas
⚠️ Si las cards no se actualizan: Ejecutar ./update-changelog-complete.sh para sincronizar git_history.txt y actualizar changelog.html. Este script siempre verifica y corrige desincronizaciones.
Problema común: git_history.txt desincronizado con commits reales
Solución: Ejecutar ./update-changelog-complete.sh que:
• Detecta commits faltantes automáticamente
• Sincroniza git_history.txt con todos los commits
• Actualiza changelog.html con los datos correctos

Verificación:
wc -l git_history.txt (debe coincidir con total de commits)
git log --format="%H" --all | wc -l (comparar números)

9
Renderizado de Cards
La función renderCommits() crea una card .changelog-item única para cada commit, validando que no haya duplicados y que toda la información esté presente.
Validaciones:
• Verifica que el commit tenga hash válido
• Evita duplicados usando Set de hashes
• Valida que el mensaje exista
• Maneja casos donde autor/email estén vacíos
• Agrega atributo data-commit-hash único
Ejemplo de Card Generada:
Título: Update: Implementar múltiples teams y funcionalidad hide section
Hash: b5bc3fb
Autor: Ubits (ubits@macbookpro.lan)
Fecha: 2025-12-02 15:08:25
Enlace: GitHub commit link
10
Inserción en el DOM
Todas las cards se insertan en el contenedor #changelogContainer y se actualiza el contador de commits totales y la fecha de última actualización.
Resultado:
• Cada commit tiene su propia card única
• Las cards están ordenadas (más reciente primero)
• Se muestra el total de commits
• Se registra la fecha de última actualización
• Se valida que el número de cards coincida con commits
10
Verificación y Visualización de la Card del Último Commit
PASO MANDATORIO ANTES DE FINALIZAR: Se verifica que el último commit creado tenga su card correctamente generada y se muestra su información para confirmar que el proceso se completó exitosamente.
Proceso:
1. Se obtiene el último commit usando git log -1
2. Se verifica que el commit esté presente en git_history.txt (debe ser la primera línea)
3. Se verifica que el commit esté presente en realCommits (debe ser el primer elemento del array)
4. Se confirma que la primera card en el DOM corresponda al commit más reciente
5. Se valida que el ordenamiento sea correcto (más reciente primero)
6. Se muestra la información del último commit (hash, mensaje, autor, fecha)
7. Se valida que el enlace a GitHub funcione correctamente
Validaciones CRÍTICAS:
• El hash del último commit debe ser la primera línea en git_history.txt
• El último commit debe ser el primer elemento en realCommits
• La primera card en el DOM debe tener el hash del último commit
• La card debe tener el atributo data-commit-hash correcto
• El mensaje del commit debe coincidir
• La fecha y autor deben ser correctos
• El ordenamiento debe ser descendente (más reciente primero)
• El enlace a GitHub debe ser válido
⚠️ Si la primera card no es el último commit, hay un problema de ordenamiento que debe corregirse
11
Revertir a un Commit Específico desde las Cards
FUNCIONALIDAD CRÍTICA: Cada card del changelog contiene el hash completo del commit en el atributo data-commit-hash, permitiendo revertir el proyecto a cualquier estado anterior usando el nombre del commit o su hash.
Información disponible en cada card:
• Hash corto (7 caracteres): Visible en el enlace al final de cada card
• Hash completo: Disponible en el atributo data-commit-hash de la card
• Mensaje del commit: Título de la card (hacer clic para ver en GitHub)
• Fecha y autor: Información completa del commit
Proceso para revertir a un commit:
Opción 1: Usando el nombre del commit (más fácil)
1. Abrir la consola del navegador (F12 → Console)
2. Ejecutar: getCommitHashByName("nombre del commit")
3. La función mostrará el hash completo y el comando para checkout
4. Copiar el hash y ejecutar: git checkout <hash>

Opción 2: Buscando manualmente
1. Localizar la card del commit deseado usando el buscador en la parte superior
2. Copiar el hash completo del commit (hacer clic derecho en la card → Inspeccionar → buscar data-commit-hash)
3. Alternativamente, copiar el hash corto mostrado en el enlace (7 caracteres)
4. Ejecutar en la terminal: git checkout <hash-completo-o-corto>
5. Para volver a la última versión: git checkout main (o el nombre de tu rama)
Comandos útiles:
• Buscar commit por nombre: En consola del navegador: getCommitHashByName("nombre")
• Ver cambios de un commit: git show <hash>
• Ver archivos modificados: git show --name-only <hash>
• Crear rama desde un commit: git checkout -b nueva-rama <hash>
• Revertir cambios (sin perder historial): git revert <hash>
• Resetear a un commit (peligroso, perder cambios posteriores): git reset --hard <hash>
• Buscar commit por mensaje en git: git log --all --grep="nombre"
Validación:
• Cada card debe tener el atributo data-commit-hash con el hash completo
• El hash debe ser válido y existir en el repositorio
• El hash debe corresponder al commit mostrado en la card
• El enlace a GitHub debe funcionar y mostrar el commit correcto
• La función getCommitHashByName() está disponible globalmente para buscar por nombre
⚠️ Siempre verificar el hash antes de hacer checkout en producción
Ejemplo de uso de getCommitHashByName():
getCommitHashByName("Fix: Botón team-add-cta")
Esto buscará cualquier commit cuyo mensaje contenga "Fix: Botón team-add-cta" y mostrará:
• El hash completo del commit
• El hash corto
• El comando completo para hacer checkout
